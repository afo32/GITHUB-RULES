• git remote

    se usa para administrar conexiones a otros repositorios (remotos), como crearlas, verlas y eliminarlas. Permite usar nombres cortos (como origin) en lugar de las URL completas en otros comandos de Git como fetch, pull y push. Las opciones comunes incluyen git remote -v para ver las URL de los remotos y git remote add para agregar uno nuevo

    Uso: Ver conexiones remotas: git remote: Muestra los nombres cortos de todos los repositorios remotos configurados. git remote -v: Muestra los nombres cortos junto con sus URL de origen (fetch) y destino (push). Agregar una conexión remota: git remote add : Añade una nueva conexión a un repositorio remoto. Por ejemplo, git remote add mi-remoto https://github.com/usuario/mi-repo.git. Cambiar el nombre de un remoto: git remote rename : Cambia el nombre de un remoto existente. Por ejemplo, git remote rename origin github. Eliminar una conexión remota: git remote rm : Elimina una conexión remota existente. Mostrar detalles de un remoto específico: git remote show : Muestra información detallada sobre un remoto en particular, como su URL de obtención y la rama principa

  • git init

    Puedes crear un nuevo repositorio cuando lo desees durante el proyecto, ¡no tiene que ser al principio! Lo único esencial para hacer esto es que el proyecto no tenga otro repositorio ya creado. Para crear un repositorio, navega en tu línea de comando al directorio raíz del proyecto y ejecuta el comando git init. Recuerda que el directorio no necesita estar vacío. Esto creará un directorio .git en el directorio del proyecto. Asegúrate de que la carpeta se haya creado correctamente (puedes ejecutar el comando ls -a para leer el contenido del directorio en la línea de comandos).

    Uso: Crear un nuevo repositorio

  • git add .

    Indícale a GIT qué archivos incluir en el commit, con git add .. Si un archivo no ha cambiado desde el commit anterior (el commit "principal"), GIT lo incluirá automáticamente en el commit que estás a punto de realizar. Solo deberás agregar los archivos que hayas creado o modificado recientemente. Ten en cuenta que agrega directorios de forma recursiva, así que git add . agregará todo lo que ha cambiado.

    Uso: Agregar al commit todo lo nuevo q has escrito

  • git commit

    Llama a git commit para crear el objeto de confirmación. El nuevo commit object tendrá el HEAD actual como su principal (después de que se complete el commit, el HEAD apuntará al nuevo commit object).

    Uso: despues de usar git add . , se utiliza git commit -m "lo q sea" para agregar lo nuevo al commit. IMPORTANTE siempre poner -m despues de commit

  • git push

    es un comando que envía los cambios confirmados localmente (los "commits") a un repositorio remoto. Es parte del flujo de trabajo colaborativo, permitiendo que otros desarrolladores accedan a tus actualizaciones después de haber confirmado los cambios en tu máquina local. La sintaxis básica es {git push }

    Uso: subir los commits desde tu rama (branch) local en tu repositorio git local al repositorio remoto.

  • git log

    muestra un registro de todos los commits desde HEAD hasta el commit inicial

    Uso: mostrar el registro de commits q se hayan hecho en el proyecto

  • git status

    muestra qué archivos han cambiado entre el estado actual del proyecto y el HEAD. Los archivos se clasifican en una de las tres categorías: (1) Archivos nuevos que no se han agregado (con git add), (2) Archivos modificados que no se han agregado y (3) Archivos que se han agregado

    Uso: los cambios en los commits del repositorio

  • git diff

    muestra la diferencia entre el HEAD y el estado actual del proyecto. Con la opción --cached, compara archivos agregados contra HEAD; de lo contrario, compara los archivos que aún no se han agregado

    Uso: comparar lo q estaba hecho vs lo q has hecho nuevo

  • git checkout [head-name]

    Apunta al HEAD del commit object especificado por [head-name]. Vuelve a escribir todos los archivos en el directorio para que coincidan con los archivos almacenados en la nueva HEAD commit.

    Uso: establecer el head en la rama q se ha creado
